How it works

The parsing engine behind every layer.

Pellucid does not summarise documents. It builds a structured representation of each document's meaning — passage by passage, layer by layer — so that queries are answered with evidence, not inference.

In this section

01

Document ingest

Pellucid ingests documents in any format institutional teams actually use: PDF, Word, HTML, and EDGAR filings. The ingest pipeline normalises structure — detecting page hierarchy, footnotes, tables, and embedded exhibits — without discarding the original layout signal. Layout is evidence: a table nested inside a footnote means something different than the same table in the body of a 10-K.

Documents are never passed to a general-purpose language model as raw text. Structure-preserving ingest is the precondition for everything that follows.

PDF DOCX HTML EDGAR XML Layout-preserving

02

Semantic parsing

Each ingested document is parsed into a layered semantic graph. Every passage is classified by function: disclosure, risk factor, forward-looking statement, covenant definition, regulatory citation. Classifications are not tags appended to text — they determine how each passage participates in queries, comparisons, and audit trails.

Parsing is trained on a corpus of institutional filings with explicit human review. The engine distinguishes between a covenant and a covenant reference, between a disclosure requirement and its fulfilment, between a material change and a restatement of prior language.

03

Layered indexing

Pellucid indexes documents in three concurrent layers: structural (section headings, tables, exhibits), semantic (passage meaning, entity relationships), and temporal (version history, amendment tracking, filing sequence). A query that spans document versions does not require re-reading — the temporal index tracks what changed, where, and in which direction.

Institutional document sets are rarely static. Pellucid's index treats a corpus as a living object: new filings update the temporal layer without requiring re-indexing of unchanged content.

04

Evidence-anchored query

Every Pellucid response is anchored to specific document passages with page, section, and paragraph coordinates. Analysts can navigate from a query answer directly to the source text in the original document. The audit trail is not a log — it is the primary output format. Downstream workflows (credit memos, deal summaries, regulatory gap analyses) are produced with citations embedded at the passage level.

Pellucid does not generate text that is not already in the corpus. It surfaces, structures, and compares. What analysts receive is the document's own language, organised and made queryable.

The seven document layers.

Pellucid's semantic graph represents each document across seven distinct layers. Queries traverse any subset of layers simultaneously — enabling cross-document comparison at a precision that section-level search cannot reach.

L1

Structure

Document hierarchy — sections, subsections, page regions, headers, footers, and embedded exhibits. The scaffold all other layers attach to.

Structural
L2

Entity

Named parties, instruments, jurisdictions, and regulatory regimes identified and resolved across passages. A counterparty mentioned in twelve filings is the same node.

Semantic
L3

Obligation

Covenants, conditions precedent, representations, and warranties — classified by type and linked to the parties they bind.

Semantic
L4

Risk disclosure

Forward-looking statements, material uncertainty disclosures, and regulatory risk factors — distinguished from factual reporting passages.

Semantic
L5

Quantitative

Numerical claims — financial ratios, performance metrics, compliance thresholds — extracted with their surrounding context and units.

Semantic
L6

Cross-reference

Internal citations, external filing references, and exhibit linkages — resolved so that navigating a reference reaches the referenced passage directly.

Relational
L7

Version delta

Changes between successive filing versions of the same document — tracked at the passage level, not the section level. Material changes surface automatically.

Design principles

Built for the nature of institutional documents.

01

No free generation

Pellucid does not generate text that is not present in the source corpus. Every output passage is the document's own language. This eliminates the hallucination surface entirely, which matters when the output is a credit memo or a regulatory submission.

02

Audit-first output

The audit trail is not an optional export. It is the primary output format. Every query result includes passage coordinates so analysts can verify claims in seconds, not hours. Downstream outputs are designed to carry citations into the final deliverable.

03

Corpus as object

Document sets are treated as living objects, not static collections. When a new filing arrives, Pellucid updates the temporal index without re-processing the full corpus. This makes continuous monitoring — not just one-off analysis — operationally practical.

04

Precision over recall

Pellucid is designed for institutional use where a false positive in a credit assessment or due diligence report has real cost. The system is calibrated to return fewer results with higher precision, not more results that require manual filtering.

05

Workflow-native export

Outputs are designed to enter existing institutional workflows without transformation. Audit trails export as structured JSON for systems integration. Summaries export in formats compatible with standard deal room and research management platforms.

06

Data residency by design

Pellucid is deployed in isolated, single-tenant environments. Document corpora do not share infrastructure between clients. For clients with specific jurisdictional requirements, on-premise deployment is available.
