The interface
earns its shape

Draftform is a hardware design IDE where the workspace is not fixed. Describe what you want to build — the IDE generates the artifact and assembles the interface controls appropriate for it. Every session begins with a sentence and resolves into a manufacturable file.

The workspace

A split canvas that knows what it's showing

Architecture

Four panels. One coherent workspace.

Panel A

Chat panel — natural language input

The left pane is a scrollable conversation thread with a fixed prompt field at the bottom. Messages alternate between user prompts and AI responses — but AI responses include embedded artifact previews, generation status, and parameter summaries alongside prose. The input accepts plain language; structured CAD syntax is never required. Prompts can reference previous turns: "make the mounting holes 0.5mm larger" correctly modifies only the relevant dimension of the most recently generated artifact.

Panel B

Artifact canvas — full-bleed rendering

The right pane occupies the remaining viewport. For STL output, it renders a React Three Fiber scene with orbit controls, mesh shading, and wireframe toggle. For PCB, it opens a 2D layer viewer with net inspection. For DXF, it loads a dimensioned orthographic view.

Panel C

Adaptive toolbar — AI-generated controls

A floating control strip anchored to the bottom of the canvas. The controls present are generated alongside the artifact — they are not a fixed menu. An STL artifact yields material selector, layer visibility, and export button. A PCB artifact yields net filter, DRC checker, and Gerber export.

Design principle

The interface is generated, not configured

Most IDEs present the same tool palette regardless of what you're working on. Draftform takes a different position: the controls for a 3D mechanical part are structurally different from the controls for a PCB layout, and both are different from what you need to work with a dimensioned 2D drawing. Presenting all three simultaneously is friction. Generating only what's relevant to the current artifact is function.

This is the core design premise of Draftform: the workspace assembles itself around the artifact, rather than forcing the artifact to fit inside a fixed workspace.
