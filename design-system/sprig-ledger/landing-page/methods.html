Scientific approach

The evidentiary chain from first observation to published analysis.

Hawthorn's architecture is a methods argument. Every structural decision — offline-first storage, cryptographic session linking, protocol-driven form generation — exists to preserve the rigour that field science demands and most data tools quietly undermine.

How it works

A complete methodological chain.

  1. 01

    Protocol definition

    Every study begins with a formal protocol definition: target taxa, spatial geometry, environmental variables, sampling intervals, and required media. The protocol is the schema — everything downstream derives from it. Protocol versions are tracked and linked to all results.

  2. 02

    Field session initialisation

    Before entering the field, researchers initialise a session against a specific protocol version. Session metadata — observer ID, device ID, protocol version, date-time, GPS bounding box — is cryptographically signed at initialisation. All subsequent observations inherit this signature.

  3. 03

    Structured field observation

    Observations are entered in protocol-generated forms — not freeform. GPS coordinates, timestamps, and environmental variables are captured automatically. The device stores all data locally; sync happens when signal is available. No observation can be entered without a valid session reference.

  4. 04

    Data validation and quality control

    On sync, Hawthorn runs a validation pass: range checks against protocol-defined variable bounds, completeness checks for required fields, and spatial coherence checks against the defined transect geometry. Anomalies are flagged for investigator review — not silently discarded.

  5. 05

    Statistical analysis

    Analysis runs directly on validated observation records — no export step, no format conversion. Investigators define their statistical model, specify grouping variables, and run. All parameters are saved with the analysis run, making every result fully reproducible.

  6. 06

    Publication output

    Figures are output at the resolution and format specified by the target journal. The methods section is generated from the analysis configuration, citing correct software versions and statistical methods. The supplementary data package includes provenance-linked raw records and the full protocol definition.

Data architecture

Every record knows where it came from.

Field data has a provenance problem. Hawthorn's session linking is a cryptographic architecture: each observation carries an unforgeable reference to its protocol version, observer, device, and session state. This is not an audit log built on top of the data — it is a property of the data model itself.

Specifications

Platform capabilities in detail.

Storage architecture
SQLite on-device, encrypted at rest. Sync via secure delta protocol on reconnect. Server-side Postgres with row-level provenance metadata.
Offline capability
Full observation logging at zero signal. Taxonomic lookup tables cached on-device. GPS available independently of network. All forms functional offline.
Session signing
HMAC-SHA256 session signatures generated at initialisation. All observations reference session ID. Tamper detection on sync. Signature chain exportable for external audit.
Statistical methods
Linear and generalised linear models, mixed-effects models, non-parametric tests, ordination (PCA, NMDS, RDA). R engine under the analysis layer. Method citations auto-generated.
Output formats
SVG and PNG figures at configurable DPI. CSV, JSON, and RDS exports. Methods section in plain text, LaTeX, and Word. Journal presets for Ecology, Journal of Ecology, Oikos, and PLOS ONE.
Collaboration
Project-level access control with role differentiation (PI, field observer, analyst, read-only). All analysis runs shared with co-investigators. Protocol changes require PI approval.
