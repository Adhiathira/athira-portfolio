How it works

The workflow is already yours

Ledgerline does not impose a new process. It instruments the one you already follow.

Three capabilities, one record

01

Contextual annotation

Import a drawing — DWG, PDF, or IFC-derived sheet. Place annotation pins on any coordinate. Attach a text note, dimension, material call, or full specification entry directly to that coordinate. The annotation travels with the drawing across all revisions. When the drawing updates, the pin moves with the geometry.

Annotations are not sticky notes. They are structured records: they carry a timestamp, an author, a status, and an optional link to the governing specification entry. You can filter the annotation layer by status, trade, or revision before exporting a contractor package.

Version-aware specifications

Every specification entry is versioned automatically. The system records who wrote it, when it was modified, what the previous version said, and which drawing annotations it is linked to. There is no separate change log to maintain — the log is the record itself.

During a design review, you open a wall assembly and see four revisions. You see who made each change and what changed at each step. The conversation with the contractor becomes: "Here is revision 3. Here is what changed from revision 2 and why." That is a different conversation from "I think we changed this last month, let me find the email."

03

Contractor handoff

When a package is ready for issue, Ledgerline compiles it: drawings at the correct revision, specification entries linked to those drawings, RFI history for the relevant trade, and a cover sheet with the issue record. The package arrives complete. Not missing an attachment. Not with a stale revision mark.

You select the issue type — IFC, tender, construction, or site instruction — and the system applies the appropriate revision marking convention. A PDF of the package, a structured data export for contractor systems, and an audit-ready record are produced simultaneously from the same source.

Compatibility

Works inside your existing environment

Ledgerline reads native DWG and PDF. It does not require a BIM model. It does not require a new file format. Your drawing set continues to live in your existing CAD environment — Ledgerline operates as a linked annotation and specification layer, not a replacement for your drawing tools.

Structured exports are available in PDF, CSV, and JSON. If your contractor uses a procurement system that accepts structured data, the export maps directly. If not, the PDF package works on any device.

Principles

The record is primary

Documentation is not a deliverable to be assembled at the end of a project. It is what makes the project workable throughout. Ledgerline is designed around this conviction — the record is the work, not the summary of it.

Precision without overhead

Good architects already document well. The problem is the friction — the separate spreadsheet, the out-of-sync PDF, the annotation that doesn't survive a revision. Ledgerline removes friction from habits that already exist. It does not install rigor from scratch.

Authorship matters

Every entry has an author. Every revision has a reason. A specification that arrived without a person responsible for it is not a specification — it is a suggestion. Ledgerline keeps authorship visible because accountability is a design property of the record itself.
